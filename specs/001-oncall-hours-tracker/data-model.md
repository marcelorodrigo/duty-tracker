### Value Objects (Enums)

```java
// com.dutytracker.domain.model.EmployeeType
enum EmployeeType { INTERNAL, EXTERNAL }

// com.dutytracker.domain.model.ColorScheme
enum ColorScheme { DARK, LIGHT, AUTO }

// com.dutytracker.domain.model.StandbyRateType
enum StandbyRateType { WEEKDAY_SATURDAY, SUNDAY_HOLIDAY }

// com.dutytracker.domain.model.RateCategory
// ONCALL_* = on-call standby rate; OVERTIME_BASE = base overtime hours;
// OVERTIME_ALLOWANCE = allowance percentage entry for a time zone
enum RateCategory {
    ONCALL_WEEKDAY_SATURDAY,
    ONCALL_SUNDAY_HOLIDAY,
    OVERTIME_BASE,
    OVERTIME_ALLOWANCE
}

enum OnboardingStep { PROFILE, PREFERENCES, COMPENSATION_RATES, COMPLETE }
```

### Entities

All entities are Java **records** (immutable). Persistence IDs are `Long` (auto-generated by SQLite `INTEGER PRIMARY KEY AUTOINCREMENT`).

#### EngineerProfile

Singleton — only one row ever exists in the `engineer_profile` table.

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `Long` | PK, auto-generated |
| `employeeType` | `EmployeeType` | NOT NULL |
| `workingDays` | `Set<DayOfWeek>` | NOT NULL, at least 1 day; stored as comma-separated TEXT |
| `workStartTime` | `LocalTime` | NOT NULL; stored as TEXT `HH:mm` |
| `workEndTime` | `LocalTime` | NOT NULL; after `workStartTime` |
| `createdAt` | `Instant` | NOT NULL; stored as TEXT ISO-8601 |

**Validation rules**:
- `workingDays` must contain at least one value
- `workEndTime` must be strictly after `workStartTime`
- Only one profile may exist — `CreateEngineerProfileUseCase` errors if a profile already exists

**Profile lock rule**: Once any `RegistrationSummary` exists, the profile is immutable. `UpdateEngineerProfileUseCase` checks this and throws `ProfileLockedException` if violated.

#### UserPreferences

Singleton — only one row ever exists.

| Field | Type | Constraints |

| `id` | `Long` | PK, auto-generated |
| `colorScheme` | `ColorScheme` | NOT NULL, default `AUTO` |
| `onboardingStep` | `OnboardingStep` | NOT NULL, default `PROFILE` |

#### CompensationRate

One row per rate entry. The full Compensation Rate Table is the set of all rows. Rows are seeded from WCA defaults on first startup.

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `Long` | PK, auto-generated |
| `employeeType` | `EmployeeType` | NOT NULL |
| `rateCategory` | `RateCategory` | NOT NULL |
| `label` | `String` | NOT NULL; human-readable label, e.g., "Weekday evening (18:00–22:00)" |
| `timeFrom` | `LocalTime` | NULLABLE; only for `OVERTIME_ALLOWANCE` rows |
| `timeTo` | `LocalTime` | NULLABLE; only for `OVERTIME_ALLOWANCE` rows |
| `percentage` | `BigDecimal` | NOT NULL; e.g., `50.00` for 50% |

**Uniqueness**: `(employeeType, rateCategory, timeFrom, timeTo)` must be unique.

**Validation rules**:
- For `OVERTIME_ALLOWANCE` rows: `timeFrom` and `timeTo` must both be present and `timeTo` after `timeFrom` (midnight-wrap handled by treating `timeTo = 00:00` as next-day boundary)
- `percentage` must be ≥ 0

#### OnCallPeriod

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `Long` | PK |
| `startDateTime` | `LocalDateTime` | NOT NULL |
| `endDateTime` | `LocalDateTime` | NOT NULL; after `startDateTime` |
| `createdAt` | `Instant` | NOT NULL |

**Validation rules**:
- `endDateTime` must be after `startDateTime`
- Minimum period: 1 hour

**Relationships**:
- Has many `HolidayOverride` (via `on_call_period_id` FK)
- Has many `OnCallDayEntry` (computed + persisted)
- Has many `Incident`

#### HolidayOverride

A calendar date manually flagged as a public holiday within an on-call period.

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `Long` | PK |
| `onCallPeriodId` | `Long` | FK → `on_call_period`, NOT NULL |
| `date` | `LocalDate` | NOT NULL |

**Uniqueness**: `(onCallPeriodId, date)` must be unique.

---

#### OnCallDayEntry

One row per calendar day covered by an `OnCallPeriod`. Calculated by `CalculateOnCallDayEntriesUseCase` and persisted. The engineer may override any field directly (sets `manualOverride = true`).

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `Long` | PK |
| `onCallPeriodId` | `Long` | FK → `on_call_period`, NOT NULL |
| `date` | `LocalDate` | NOT NULL |
| `hours` | `BigDecimal` | NOT NULL; ≥ 0, ≤ 24 (enforced on calculated entries; engineer overrides are unrestricted) |
| `rateType` | `StandbyRateType` | NOT NULL |
| `capped` | `boolean` | True if the 15-hour cap was applied |
| `timeForTimeFlag` | `boolean` | True if this day triggers a time-for-time advisory |
| `manualOverride` | `boolean` | True if the engineer edited the calculated value |

---

#### Incident

A discrete work event triggered by on-call responsibilities (or recorded for time-for-time purposes).

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `Long` | PK |
| `onCallPeriodId` | `Long` | FK → `on_call_period`, NULLABLE (null = not on-call, time-for-time scenario) |
| `date` | `LocalDate` | NOT NULL |
| `startTime` | `LocalTime` | NOT NULL |
| `endTime` | `LocalTime` | NOT NULL; if `endTime` ≤ `startTime`, it is treated as crossing midnight |
| `createdAt` | `Instant` | NOT NULL |

**Validation rules**:
- `date` must not be in the future
- If `onCallPeriodId` is present, `date` must fall within the associated `OnCallPeriod`

---

#### OvertimeEntry

Calculated line items derived from an `Incident`. One base entry per incident segment plus one allowance entry per applicable time zone within that segment.

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `Long` | PK |
| `incidentId` | `Long` | FK → `incident`, NOT NULL |
| `overtimeHours` | `BigDecimal` | NOT NULL; rounded up to next full hour |
| `allowanceHours` | `BigDecimal` | NULLABLE; only present on `OVERTIME_ALLOWANCE` entries |
| `allowancePercentage` | `BigDecimal` | NULLABLE; only present on `OVERTIME_ALLOWANCE` entries |
| `timeFrom` | `LocalTime` | NULLABLE; zone start for allowance entries |
| `timeTo` | `LocalTime` | NULLABLE; zone end for allowance entries |
| `isAllowanceEntry` | `boolean` | False = base overtime hours entry; True = allowance percentage entry |
| `manualOverride` | `boolean` | True if the engineer edited the calculated value |

---

#### RegistrationSummary

A named, persisted snapshot of all on-call day entries and overtime entries for a given period. Created automatically when the engineer first views the reporting screen for an on-call period, or manually.

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `Long` | PK |
| `label` | `String` | NOT NULL; e.g., "Week 15 — Apr 6–12, 2026" |
| `periodStart` | `LocalDate` | NOT NULL |
| `periodEnd` | `LocalDate` | NOT NULL |
| `createdAt` | `Instant` | NOT NULL |
| `updatedAt` | `Instant` | NOT NULL |

### Domain Exceptions

| Exception | Trigger |
|-----------|---------|
| `ProfileAlreadyExistsException` | `CreateEngineerProfileUseCase` called when profile exists |
| `ProfileLockedException` | Profile edit attempted after registrations exist |
| `OnboardingNotCompletedException` | Any registration use case called before onboarding is `COMPLETE` |
| `InvalidOnCallPeriodException` | `endDateTime` ≤ `startDateTime`, or period too short |
| `InvalidIncidentException` | Incident date outside on-call period, or other validation failure |
| `HolidayAlreadyRegisteredException` | Duplicate `(onCallPeriodId, date)` holiday override |
| `IncidentDuringWorkingHoursException` | All incident hours fall within normal working hours — no overtime applicable |
| `OvertimeDayOffException` | Incident on a day off — time-for-time applies instead |

### `V1__create_schema.sql`

```sql
CREATE TABLE engineer_profile (
    id              BIGSERIAL PRIMARY KEY,
    employee_type   VARCHAR(20) NOT NULL CHECK (employee_type IN ('INTERNAL','EXTERNAL')),
    working_days    VARCHAR(100) NOT NULL,  -- comma-separated DayOfWeek names
    work_start_time TIME NOT NULL,
    work_end_time   TIME NOT NULL,
    created_at      TIMESTAMP NOT NULL DEFAULT now()
);

CREATE TABLE user_preferences (
    id              BIGSERIAL PRIMARY KEY,
    color_scheme    VARCHAR(10) NOT NULL DEFAULT 'AUTO'
                    CHECK (color_scheme IN ('DARK','LIGHT','AUTO')),
    onboarding_step VARCHAR(30) NOT NULL DEFAULT 'PROFILE'
                    CHECK (onboarding_step IN ('PROFILE','PREFERENCES','COMPENSATION_RATES','COMPLETE'))
);

CREATE TABLE compensation_rate (
    id              BIGSERIAL PRIMARY KEY,
    employee_type   VARCHAR(20) NOT NULL CHECK (employee_type IN ('INTERNAL','EXTERNAL')),
    rate_category   VARCHAR(40) NOT NULL CHECK (rate_category IN
                    ('ONCALL_WEEKDAY_SATURDAY','ONCALL_SUNDAY_HOLIDAY','OVERTIME_BASE','OVERTIME_ALLOWANCE')),
    label           VARCHAR(100) NOT NULL,
    time_from       TIME,
    time_to         TIME,
    percentage      NUMERIC(10,4) NOT NULL,
    UNIQUE (employee_type, rate_category, time_from, time_to)
);

CREATE TABLE on_call_period (
    id              BIGSERIAL PRIMARY KEY,
    start_date_time TIMESTAMP NOT NULL,
    end_date_time   TIMESTAMP NOT NULL,
    created_at      TIMESTAMP NOT NULL DEFAULT now()
);

CREATE TABLE holiday_override (
    id                BIGSERIAL PRIMARY KEY,
    on_call_period_id BIGINT NOT NULL REFERENCES on_call_period(id) ON DELETE CASCADE,
    date              DATE NOT NULL,
    UNIQUE (on_call_period_id, date)
);

CREATE TABLE on_call_day_entry (
    id                BIGSERIAL PRIMARY KEY,
    on_call_period_id BIGINT NOT NULL REFERENCES on_call_period(id) ON DELETE CASCADE,
    date              DATE NOT NULL,
    hours             NUMERIC(10,4) NOT NULL,
    rate_type         VARCHAR(25) NOT NULL CHECK (rate_type IN ('WEEKDAY_SATURDAY','SUNDAY_HOLIDAY')),
    capped            BOOLEAN NOT NULL DEFAULT FALSE,
    time_for_time_flag BOOLEAN NOT NULL DEFAULT FALSE,
    manual_override   BOOLEAN NOT NULL DEFAULT FALSE
);

CREATE TABLE incident (
    id                BIGSERIAL PRIMARY KEY,
    on_call_period_id BIGINT REFERENCES on_call_period(id) ON DELETE SET NULL,
    date              DATE NOT NULL,
    start_time        TIME NOT NULL,
    end_time          TIME NOT NULL,
    created_at        TIMESTAMP NOT NULL DEFAULT now()
);

CREATE TABLE overtime_entry (
    id                   BIGSERIAL PRIMARY KEY,
    incident_id          BIGINT NOT NULL REFERENCES incident(id) ON DELETE CASCADE,
    overtime_hours       NUMERIC(10,4) NOT NULL,
    allowance_hours      NUMERIC(10,4),
    allowance_percentage NUMERIC(10,4),
    time_from            TIME,
    time_to              TIME,
    is_allowance_entry   BOOLEAN NOT NULL DEFAULT FALSE,
    manual_override      BOOLEAN NOT NULL DEFAULT FALSE
);

CREATE TABLE registration_summary (
    id           BIGSERIAL PRIMARY KEY,
    label        VARCHAR(200) NOT NULL,
    period_start DATE NOT NULL,
    period_end   DATE NOT NULL,
    created_at   TIMESTAMP NOT NULL DEFAULT now(),
    updated_at   TIMESTAMP NOT NULL DEFAULT now()
);
```

## Core Calculation Logic

### On-Call Day Entry Calculation (`CalculateOnCallDayEntriesUseCase`)

```
Input: OnCallPeriod + EngineerProfile + List<HolidayOverride> + PublicHolidayGateway

For each calendar day D within [period.startDate, period.endDate]:
  1. Determine hours on-call for D:
     - If D == startDate: hours = 24 - startTime.hour (proportional to start)
     - If D == endDate:   hours = endTime.hour (proportional to end)
     - Otherwise:         hours = 24
     (Actual hours based on period start/end times, respecting midnight boundary)

  2. Determine rateType:
     - If D is Sunday OR (D is in holidayOverrides OR isPublicHoliday(D)):
         rateType = SUNDAY_HOLIDAY
     - Else: rateType = WEEKDAY_SATURDAY

  3. Determine cap:
     - isWorkingDay = profile.workingDays.contains(D.dayOfWeek)
     - If isWorkingDay AND hours > 15: cap to 15, capped = true
     - (Non-working days: no cap, max 24)

  4. timeForTimeFlag:
     - If isWorkingDay AND engineer took day off (no direct signal in model — engineer marks
       day off by setting hours manually; flag is advisory only): timeForTimeFlag = true
     - Note: "day off" detection relies on the engineer explicitly indicating a day off
       via the UI (a checkbox per day in the on-call period entry screen)

Output: List<OnCallDayEntry>
```

### Overtime Entry Calculation (`CalculateOvertimeEntriesUseCase`)

```
Input: Incident + EngineerProfile + List<CompensationRate> (OVERTIME_ALLOWANCE rows)
       + PublicHolidayGateway

Pre-checks:
  - If incident.date is a "day off" (engineer-flagged): throw OvertimeDayOffException
  - Split incident into segments outside normal working hours:
      workStart = profile.workStartTime, workEnd = profile.workEndTime
      Exclude [workStart, workEnd) from incident time range (unless date is holiday)
  - If all hours are within working hours: throw IncidentDuringWorkingHoursException

For each remaining segment [segFrom, segTo]:
  1. Split segment by OVERTIME_ALLOWANCE time zone boundaries from CompensationRate table
  2. For each sub-segment:
     a. roundedHours = ceil(duration in hours) → minimum 1 hour
     b. Create OvertimeEntry (isAllowanceEntry=false) with overtimeHours = roundedHours
     c. Find matching CompensationRate row for this time zone
     d. If allowance applies: create OvertimeEntry (isAllowanceEntry=true) with
        allowanceHours = roundedHours, allowancePercentage = rate.percentage

Output: List<OvertimeEntry>
```

> **Note**: The "day off" flag is stored on `OnCallDayEntry.timeForTimeFlag`. When an engineer marks a day as a day off in the UI, the frontend must set this flag and the overtime calculation must check it before proceeding.
